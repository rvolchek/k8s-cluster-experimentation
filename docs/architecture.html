Workflow 1: install something new

  1. On the MacBook, add platform/<name>/application.yaml pointing at the component's Helm chart, following platform/kuberay/application.yaml.
  2. Push to GitHub (path 4).
  3. In the Argo CD UI (path 1), Sync the root app to register the new Application, review its diff, then Sync it (paths 5 and 6).
  4. Check that it runs with k9s (path 2) or Headlamp (path 1).
  5. If it has a web UI, add a Tailscale Ingress to the repo, following bootstrap/argocd/ingress.yaml.

[UNVERIFIED SLOP]Workflow 2: deploy a model
  1. On the MacBook, write a KServe InferenceService that runs vLLM: model ID, GPU request and runtime.
  2. Push to GitHub, then Sync in Argo CD (paths 4, 5 and 6).
  3. KServe starts vLLM pods on the GPU.
  4. Call the model from the MacBook with curl or an OpenAI-compatible client at its tailnet HTTPS address (path 3).

Open points: the vLLM runtime settings in KServe, how KServe endpoints are exposed through the tailnet, GPU support on k3s, and keeping model download tokens out of the public repo.

[UNVERIFIED SLOP]Workflow 3: run a KFP experiment
  1. On the MacBook, write the pipeline in Python with the KFP SDK.
  2. Submit it to the KFP API at its tailnet HTTPS address (path 3). Argo CD is not involved.
  3. KFP starts run pods on ronen-minty.
  4. Watch the run in the KFP UI (path 1).

Open points: KFP install method on k3s, and whether the KFP API accepts SDK calls through the Tailscale ingress.
